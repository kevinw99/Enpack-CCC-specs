# Design: 研发AI应用需求 (R&D AI Application Requirements)

## Approach

P22 是一个需求汇总规格，包含6个独立的AI应用方向。每个方向在验证可行性后，可独立演化为子规格或独立项目。设计原则：

1. **统一收口**: 所有研发AI需求在此统一管理和排序
2. **独立推进**: 每个需求独立评估、设计和实施
3. **复用优先**: 尽量复用现有系统（P20 MCP、P11 实验分析、P13 文档处理等）
4. **渐进交付**: 从最小可用版本开始，逐步扩展

## 需求分类与架构定位

## 各需求详细设计

### N-02: 可行性分析（P0 优先）

**与现有系统的关系**:
- R22（AI实验因子筛选）已在推进，是N-02的一个子场景
- P20（MCP知识库）提供工艺知识检索能力
- P11（实验数据分析）提供历史实验数据分析能力

**架构**:
```
用户输入                    知识支撑                    输出
┌──────────┐    ┌──────────────────────┐    ┌──────────────┐
│ 候选方案   │    │ P20 MCP 知识库        │    │ 可行性评估报告 │
│ - 配方参数 │───►│ - 工艺文档            │───►│ - 方案排序    │
│ - 材料选择 │    │ - 历史实验（P11）      │    │ - 技术指标预判│
│ - 工艺条件 │    │ - 技术标准            │    │ - 知识库依据  │
└──────────┘    │ R22 因子分析引擎       │    │ - 知识缺口提示│
                └──────────────────────┘    └──────────────┘
```

**实现路径**: 在R22基础上扩展，不重建。

---

### N-05: 体系文件辅助（P0 优先）

**架构**:
```
输入                        知识支撑                    输出
┌──────────────┐    ┌──────────────────┐    ┌──────────────┐
│ 体系文件      │    │ 标准要求知识库     │    │ 合规检查报告  │
│ (Word/PDF/MD) │───►│ - IATF 16949     │───►│ - 逐条对照    │
│              │    │ - 客户审厂要求    │    │ - 问题清单    │
│              │    │ - 行业最佳实践    │    │ - 修改建议    │
└──────────────┘    └──────────────────┘    └──────────────┘
```

**实现步骤**:
1. 将16949标准条款结构化（可手动整理或用LLM辅助）
2. 开发文件审核MCP工具：输入文件 → 对照标准 → 输出差距
3. 开发文件生成辅助：基于模板+标准要求生成草稿

### N-03: 专利分析系统（P1）

**架构**:
```
输入               处理管线                          输出
┌─────────┐    ┌─────────────────────────────┐    ┌──────────────┐
│ 专利PDF  │    │ 1. PDF解析（复用P13）         │    │ 专利分析报告  │
│ (批量)   │───►│ 2. 结构化提取（LLM）          │───►│ - 申请人分布  │
│          │    │    - 申请人/日期/技术领域     │    │ - 时间趋势    │
│          │    │    - 权利要求/技术方案        │    │ - 地域分布    │
│          │    │ 3. 分类标引（自动+人工校验）   │    │ - 技术功效矩阵│
│          │    │ 4. 统计分析                  │    │ - 关键专利摘要│
│          │    │ 5. 报告生成                  │    └──────────────┘
│          │    └─────────────────────────────┘
└─────────┘
```

### N-01: 文献检索系统（P1）

**架构**:
```
配置                   定时任务                       输出
┌──────────┐    ┌─────────────────────────┐    ┌──────────────┐
│ 研究主题  │    │ 1. 调用学术搜索API        │    │ 文献汇总报告  │
│ 检索范围  │───►│ 2. 去重（vs已收录文献）    │───►│ - 新文献列表  │
│ 更新频率  │    │ 3. LLM摘要+分类          │    │ - 分类归档    │
│          │    │ 4. 入库+通知             │    │ - 关键发现    │
└──────────┘    └─────────────────────────┘    └──────────────┘
```

**数据源**: Google Scholar API, Semantic Scholar API, CNKI（如有API）, arXiv

### N-06: 人员出勤管理（P3，建议非AI方案）

不需要AI能力，建议用 Metabase/Grafana + OA系统数据 实现。如果研发坚持需要，可作为简单Web看板开发。

## 技术选型

| 组件 | 方案 | 备注 |
|------|------|------|
| LLM | Claude / DeepSeek | 按需选择，成本敏感任务用DeepSeek |
| PDF解析 | MinerU / PyMuPDF | 复用P13已有能力 |
| 知识检索 | P20 MCP | 复用已有向量检索 |
| 定时任务 | cron / APScheduler | N-01/N-04需要 |
| 报告生成 | Markdown → PDF (Typst) | 复用已有管线 |
| Web UI | Streamlit / FastAPI | 轻量快速，按需求定 |
