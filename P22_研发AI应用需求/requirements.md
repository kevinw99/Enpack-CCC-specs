# Requirements: 研发AI应用需求 (R&D AI Application Requirements)

## Overview

汇总研发部门提出的AI应用需求，涵盖文献检索、可行性分析、专利分析、项目申报、体系文件、人员管理六个方向。这些需求与P18（样本问题收集）不同——P18收集的是"问答型"需求（员工问一个问题，AI查数据回答），而本规格的需求是**独立的AI应用系统/工作流**，每个都有特定的输入、处理流程和输出形式。

**需求来源**: 步院长/研发团队，2026-04-12

## 与现有规格的关系

| 规格 | 关系 |
|------|------|
| P18 样本问题收集 | P18是问答型需求，本规格是系统/工作流型需求，互补不重叠 |
| P20 MCP知识库服务 | 部分需求（如N-02可行性分析）可复用MCP知识库能力 |
| R22 AI实验因子筛选 | R22是本规格N-02的一个具体实例（凹凸点因子筛选），本规格覆盖更广 |
| P11 实验数据分析建模 | P11是"实验后"数据分析，本规格N-02是"实验前"可行性分析 |

## 需求清单

### N-01: 文献检索系统

**场景**: 研发正在或将要开展的项目，需要持续跟踪相关文献动态。

**需求描述**:
- 针对指定研究主题，定时搜索学术文献和技术资料
- 对检索结果进行汇总、归类、摘要生成
- 定期输出文献综述报告

**输入**: 研究主题关键词、检索范围、更新频率
**输出**: 定期文献汇总报告（新论文列表、分类、关键发现摘要）
**特点**: 持续性自动化任务，非一次性问答

**实现思路**:
- 对接学术搜索API（Google Scholar、Semantic Scholar、CNKI等）
- 定时任务调度（每周/每两周）
- LLM进行摘要和分类

**复杂度**: 中等
**优先级**: 待评估

---

### N-02: 可行性分析

**场景**: 研发在开展新实验或新工艺前，需要对试验配方、材料、工艺做初步筛选。

**需求描述**:
- 输入候选配方/材料/工艺参数
- AI结合知识库中的已有工艺知识和实验数据，分析可行性
- 对性能等技术指标做预判
- 输出筛选建议和依据

**输入**: 候选方案列表（配方/材料/工艺参数）
**输出**: 可行性评估报告（每个方案的可行性评分、技术指标预判、推荐排序、知识库依据）
**特点**: 深度分析工具，需要结合知识库的工艺知识

**与R22的关系**: R22（AI实验因子筛选）是本需求的一个具体实例，聚焦于"因子筛选→实验方案精简"。N-02范围更广，覆盖配方、材料、工艺的综合可行性分析。

**复杂度**: 高
**优先级**: 高（研发核心需求）

---

### N-03: 专利分析系统

**场景**: 对技术领域的专利进行系统性分析，支撑研发方向决策和知识产权布局。

**需求描述**:
- 导入专利文档（PDF），AI进行专利解读
- 自动提取专利数据（申请人、申请日、技术领域、权利要求等）
- 分类标引，建立专利数据库
- 自动分析：申请人分布、申请趋势、地域分布、技术功效矩阵
- 生成专利分析报告

**输入**: 专利PDF文件（批量）
**输出**: 专利分析报告（申请人排名、时间趋势图、技术功效矩阵、关键专利摘要）
**特点**: 文档处理+分析流水线，需要PDF解析能力

**实现思路**:
- PDF解析（可复用P13大文档分块处理能力）
- 结构化信息提取（LLM + 规则）
- 统计分析与可视化
- 报告生成

**复杂度**: 中等
**优先级**: 中

---

### N-04: 项目申报辅助

**场景**: 跟踪政府各级科技政策，评估与公司的匹配度，辅助项目申报。

**需求描述**:
- 自动获取国家级、省级、市级政策文件（官网、公众号等）
- 对政策进行解读，提取申报条件和要求
- 分析政策与公司情况的适配度
- 评估申报通过率
- 提供申报建议和改善方向

**输入**: 政策来源渠道配置、公司资质信息
**输出**: 政策匹配报告（适配政策列表、匹配度评分、申报建议、改善方向）
**特点**: 需要外部信息采集+持续更新

**实现思路**:
- 政策信息采集（网页爬取/RSS/API）
- 政策结构化解读（LLM提取申报条件）
- 与公司档案匹配（利用知识库01_公司档案）
- 定期更新

**复杂度**: 高
**优先级**: 中

---

### N-05: 体系文件辅助

**场景**: 编写和审核体系文件（如IATF 16949），确保符合客户审厂和体系要求。

**需求描述**:
- AI辅助编写体系文件（基于模板和标准要求）
- 对已有体系文件进行合规性检查
- 识别问题点并提供修改建议
- 确保符合客户审厂和16949体系的要求

**输入**: 体系文件（草稿或现有版本）、适用标准（16949等）
**输出**: 合规检查报告（问题清单、修改建议、合规评分）或辅助生成的文件草稿
**特点**: 文档级操作，需要标准知识

**实现思路**:
- 将16949等标准要求结构化入知识库
- LLM对照标准逐条审核文件
- 输出差距分析和修改建议

**复杂度**: 中等
**优先级**: 高（客户审厂需求明确）

---

### N-06: 人员出勤管理看板

**场景**: 管理层需要了解研发人员的出差、请假等出勤情况。

**需求描述**:
- 汇总研发人员出差、请假等出勤信息
- 以看板形式展示给管理层
- 目的是支撑人员调度和管理决策

**输入**: 出勤数据（OA系统/考勤系统）
**输出**: 可视化看板（人员状态、出勤统计）
**特点**: 数据看板，更偏BI工具而非AI应用

**复杂度**: 低（技术上简单，但需对接OA/考勤系统）
**优先级**: 最低（最后实施）

## 优先级评估

| 优先级 | 需求 | 理由 |
|--------|------|------|
| **P0 — 立即推进** | N-02 可行性分析 | 研发核心需求，R22已在推进中，可扩展 |
| **P0 — 立即推进** | N-05 体系文件 | 客户审厂需求明确，实现路径清晰 |
| **P1 — 短期** | N-03 专利分析 | 技术成熟（PDF解析+LLM），价值明确 |
| **P1 — 短期** | N-01 文献检索 | 需要外部API接入，但技术不复杂 |
| **P2 — 中期** | N-04 项目申报 | 需要外部政策采集+持续维护，较复杂 |
| **P3 — 最后实施** | N-06 人员出勤 | 纳入项目范围，最后实施 |

## 实施建议

### 第一批（M1-M2）
- **N-02 可行性分析**: 在R22基础上扩展，从因子筛选扩展到配方/材料/工艺综合可行性
- **N-05 体系文件**: 将16949标准入库，开发审核工具

### 第二批（M2-M3）
- **N-03 专利分析**: 开发PDF解析+分析流水线
- **N-01 文献检索**: 对接学术搜索API，建立定时任务

### 第三批（M3+）
- **N-04 项目申报**: 政策采集+匹配系统
- **N-06 人员出勤**: 评估是否纳入或转交IT
