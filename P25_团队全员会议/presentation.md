## 第一部分：愿景与战略（15分钟）

### 我们是谁

**深圳凌邦德智能科技有限公司**（LeapBound AI）是由翁氏家族成员以私人名义出资设立的 AI 应用公司，以独立法人运营。

- **使命**：用 AI 技术赋能传统行业数字化转型，解决真实商业问题，产生可量化的商业价值
- **愿景**：成为中国领先的垂直行业 AI 应用公司

### 核心定位

我们不做大模型，不做通用工具。我们做的是：**把 AI 真正落地到具体的行业场景中，解决实际问题**。

### V1 是什么？为什么从 CCC 开始？

V1（制造 AI 业务线）选择英联复合集流体（CCC）作为第一个深度客户，原因：

1. **真实的工业环境**：CCC 有真实的生产数据、真实的业务问题、真实的用户反馈——这是纯软件公司买不到的
2. **数据护城河**：积累的生产数据是核心资产，形成竞争壁垒
3. **方法论验证**：在 CCC 验证的每一个 AI 能力，都可以标准化后复制到其他行业

### 战略路径：先深后广

```
CCC（做深做透）→ EOE 产线 → 英联总部 → 其他制造企业
```

在 CCC 先把方法论跑通，形成"英联 AI 部署范式"，然后向外复制。

## 第三部分：MCP 架构与部署计划（15分钟）

### 什么是 MCP？

**MCP（Model Context Protocol）** 是一个开放标准协议，让 AI 助手能够安全地连接到企业的数据系统。

简单理解：**MCP 就像一个"万能插头"**——

- AI 助手（如 Claude、DeepSeek）是"电器"
- 公司的知识库、ERP 系统是"电源"
- MCP 是"插座标准"——让电器能安全地接入电源

### 我们的双 MCP 架构

```
┌─────────────────────────────────────────────┐
│           前端工具（用户使用）                  │
│                                              │
│   ┌──────────────────────────────────┐      │
│   │        Cursor / Cherry Studio     │      │
│   │  （所有用户：技术人员 + 非技术人员） │      │
│   └────────────────┬─────────────────┘      │
│                    │  MCP 协议                │
├────────────────────┼─────────────────────────┤
│                    │                          │
│   ┌────────────────▼─────────────────┐      │
│   │    AI 大模型（可切换）              │      │
│   │    DeepSeek / Claude / 其他       │      │
│   └────┬──────────────────────┬──────┘      │
│        │                      │              │
│   ┌────▼─────┐          ┌────▼─────┐       │
│   │ 知识库 MCP │          │ ERP MCP  │       │
│   │  (李桁)    │          │ (梁咏芝)  │       │
│   └────┬─────┘          └────┬─────┘       │
│        │                      │              │
│   ┌────▼─────┐          ┌────▼─────┐       │
│   │ 47份文档   │          │ 金蝶云ERP │       │
│   │ 1345语义块 │          │ 库存/物料  │       │
│   └──────────┘          └──────────┘       │
└─────────────────────────────────────────────┘
```

### 前端工具选择

支持 MCP 协议的客户端工具越来越多，我们当前主要考虑以下选项：

| 工具 | 类型 | MCP 支持 | 模型灵活性 | 国内可用 | 适合谁 |
|------|------|----------|------------|----------|--------|
| **Cursor** | AI IDE | 原生支持 | DeepSeek/Claude/等 | 可用 | 技术人员 + 非技术人员 |
| **Cherry Studio** | AI 对话客户端 | 原生支持 | 集成 16+ 模型（含 DeepSeek） | 国产开源 | 非技术人员（纯对话界面） |
| **Trae** | AI IDE（字节跳动） | 原生支持 | 多模型 | 国产 | 技术人员 |
| Claude Desktop | AI 对话客户端 | 原生支持 | 仅 Claude | **中国无法使用** | — |

**当前选择：Cursor 为主，Cherry Studio 作为非技术人员备选**

核心考量：
1. **合规可用**：Claude Desktop 在中国无法使用，排除
2. **模型灵活**：Cursor 和 Cherry Studio 均支持切换 DeepSeek（成本低）、Claude（能力强）等多种模型
3. **国产替代**：Cherry Studio 是国产开源项目，纯对话界面，零学习成本，适合管理层和业务人员
4. **Trae 备选**：字节跳动的 AI IDE，国内生态好，后续可评估
5. **快速部署**：无需自研前端，安装即用

## 第五部分：研发 AI 数据建模与因子筛选（10分钟）

这部分介绍研发部门 AI 应用中最核心的一条链路：从实验数据管理到 AI 辅助因子筛选。

### P11 + R22：数据驱动的智能实验闭环

> **DOE**（Design of Experiments，实验设计法）：一种系统化的实验规划方法，通过科学地安排实验因子和水平组合，用最少的实验次数获取最多的有效信息。

```
P11 实验数据分析建模              R22 AI因子筛选
┌─────────────────────┐        ┌─────────────────────┐
│ 历史实验数据          │ 数据   │ 24+ 候选因子          │
│   ↓                  │──────→│   ↓                  │
│ 结构化管理            │ 支撑   │ AI + 知识库           │
│ 关系建模              │        │ 智能排序筛选          │
│ 参数优化              │        │ 压缩DOE方案           │
│ 预测指导              │←──────│ (100+ → 8-16 实验)   │
│   ↑                  │ 新数据 │                      │
│ 模型持续迭代          │ 回流   │ 实验执行 → 新结果     │
└─────────────────────┘        └─────────────────────┘
```

- **P11 → R22**：P11 积累的结构化历史数据，为 R22 的因子筛选提供数据支撑
- **R22 → P11**：R22 筛选出关键因子并推荐压缩 DOE 方案，实验执行后产生新数据回流到 P11，更新模型
- **循环效果**：每轮实验让 P11 模型更准确，下一轮 R22 筛选更精确

**P11 实验数据分析建模系统**（已完成 Phase 6）：
- 将分散的 MA/MC 工艺实验数据转化为结构化格式
- 建立工艺参数与产品质量的关系模型
- 目标：缩短新产品开发周期 30-50%
- **为 R22 提供数据基础**

**R22 AI 实验因子筛选**（开发中，机密项目）：
- 针对复合集流体生产中的复杂工艺缺陷（如 bump 缺陷）
- 利用知识库 + AI，从 24+ 候选因子中智能筛选关键因子
- **核心价值**：将实验方案从 100+ 次压缩到 8-16 次，大幅节省时间和成本
- 包含 Web UI，研发人员可直接操作
- 下一步需要步院长协助提供缺陷相关的工艺数据和专家判断

**这两个项目的关系**：P11 积累的结构化实验数据，是 R22 因子筛选的数据基础。P11 回答"参数和质量之间有什么关系"，R22 回答"哪些参数最关键、应该优先实验"。
