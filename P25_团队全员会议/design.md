**知识库 MCP 演示（李桁）：**

- 准备对比：同一问题有 MCP vs 无 MCP 的回答

### 前端工具选择理由

**Cursor 为主，Cherry Studio 为非技术人员备选**：

1. **合规可用**：Claude Desktop 在中国无法使用，排除
2. **模型灵活**：Cursor 和 Cherry Studio 均支持切换 DeepSeek（成本低）、Claude（能力强）等多种模型
3. **国产替代**：Cherry Studio 是国产开源 AI 客户端，纯对话界面，适合非技术人员；Trae（字节跳动 AI IDE）也是备选
4. **MCP 原生支持**：无需开发前端界面，安装即用
5. **覆盖全部用户**：技术人员用 Cursor，非技术人员用 Cherry Studio

## 月度会议模板设计

标准议程（2 小时）：

1. **开场回顾**（15 min）— 上月行动项完成情况逐条检查
2. **进展汇报**（20 min）— 本月关键里程碑和指标
3. **演示展示**（40 min）— 新功能或改进的现场演示
4. **数据更新**（15 min）— 使用指标、知识库覆盖率等
5. **开放讨论**（20 min）— CCC 团队反馈、需求讨论
6. **下月计划**（10 min）— 目标、行动项分配、截止日期

## 反馈机制设计

- 会后发放简单的 Markdown 反馈表
- 5 个评分项（1-5 分）+ 2 个开放问题
- 反馈汇总后纳入下月会议改进

## 行动项追踪设计

使用 Markdown 表格，每月会议后更新：

```markdown
| # | 行动项 | 负责人 | 截止日期 | 状态 | 备注 |
|---|--------|--------|----------|------|------|
| 1 | xxx    | xxx    | yyyy-mm-dd | 待开始/进行中/已完成 | |
```

状态流转：待开始 → 进行中 → 已完成 / 延期（需说明原因）
