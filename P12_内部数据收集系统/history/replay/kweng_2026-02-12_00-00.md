# Plan: Session History Categorization System (Spec 11)

## Context

The project has 13+ Claude Code session JSONL files (~15MB total) stored at `~/.claude/projects/-Users-kweng-AI-Enpack-CCC/`. These contain complete conversation transcripts but are organized only chronologically by session, with no connection to the project entities (specs, source code projects, research topics) they discuss. The user wants to **categorize** these conversations by entity and provide human-readable replay with search/filter capabilities.

An existing JS-based session-persistence system exists at `源代码/session-persistence/` but stores by date, not by entity. This new system is a separate Python tool that complements it.

---

## What We'll Build

A Python tool (`源代码/session_history/`) that:
1. Parses Claude Code JSONL session files
2. Classifies which entities (specs, projects, etc.) each session relates to
3. Stores lightweight pointer indexes under each entity's `history/` directory
4. Generates interactive HTML + Markdown replays on demand

## Storage Model

Pointer-based (Option C): Store JSON index with message UUIDs + line numbers pointing back to original JSONL files. No data duplication. HTML/Markdown regenerated on demand.

```
规格/09_内部数据收集系统/
  └── history/
      ├── sessions-index.json    # Pointers to relevant sessions/messages
      ├── replay.html            # Interactive single-file HTML
      └── replay.md              # Readable Markdown

会话历史/                         # Project-level session history root
  ├── uncategorized/             # Sessions matching no entity
  ├── all-sessions.json          # Master index: session -> categories
  └── categorization-report.md   # Statistics
```

## Classification Algorithm

Multi-signal scoring (per message, per entity):

| Signal | Weight | Example |
|--------|--------|---------|
| File path in tool_use | 0.50 | Tool reads `规格/09_.../design.md` -> spec 09 |
| Explicit text pattern | 0.35 | "Spec #09", "规格/09_" in message |
| Keyword matching | 0.15 | "内部数据收集" in message text |

Session confidence = weighted average of matched messages. Threshold: 0.15. Sessions can belong to multiple entities.

## Key Design Decisions

1. **Python** (not JavaScript): Consistent with main codebase (chunked_processor, experiment_analyzer, doc_indexer). Zero external dependencies.
2. **Pointer-based storage**: No data duplication. Replays always reflect latest JSONL content.
3. **Shared spec numbers** (three 01_*, two 03_*): Use keyword tiebreaker; when ambiguous, assign to all with reduced confidence.
4. **Exclude thinking blocks** by default in replays (configurable).
