## 配置文件格式设计

采用简单的 YAML 格式，易于扩展：

```yaml
# 权限配置.yaml
# 最后更新: 2026-02-04

# 权限级别定义
permission_levels:
  公开: 1    # 无限制
  内部: 2    # 仅内部员工
  机密: 3    # 需特殊授权
  绝密: 4    # 禁止上传

# 部门角色定义
departments:
  - 技术管理   # 技术总监、CTO
  - 研发部
  - 生产部
  - 质量部
  - 销售部
  - 财务部
  - 人力资源部
  - 行政部

# 受限路径配置（核心配置）
restricted_paths:
  # 03_技术规范 - 核心需求
  - path: "知识库/03_技术规范"
    level: 机密
    allowed_departments:
      - 技术管理
      - 研发部
    ai_access: false
    description: "核心技术规范，仅授权技术人员可访问"

  # 可扩展：未来如有其他目录需要权限控制，在此添加
  # - path: "知识库/其他路径"
  #   level: 内部
  #   allowed_departments: [部门1, 部门2]
  #   ai_access: true

# AI访问规则
ai_rules:
  default_access: true           # 默认可访问
  blocked_levels: [机密, 绝密]   # 禁止访问的级别
```

- **子项目**：机密内容 + 母项目

| 维度 | 方案A（配置文件） | 方案B（项目分割） |
|-----|-----------------|-----------------|
| **实现复杂度** | 低 - 只需配置文件 | 中 - 需要维护两个项目 |
| **AI隔离程度** | 依赖AI遵守配置 | **更彻底** - 物理隔离 |

| **管理成本** | 低 | 较高 - 两套项目 |
| **灵活性** | 高 - 可随时调整 | 低 - 需重新分割 |
| **安全性** | 中 - 依赖检查逻辑 | **高** - 物理隔离 |
| **适用场景** | 内部权限分级 | 对外共享/AI部署 |
