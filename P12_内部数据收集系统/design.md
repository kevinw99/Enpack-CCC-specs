### 1.1.1 子路径设计原则

| 维度 | 适用场景 | 示例 |
|-----|---------|------|
| **按产线** | 生产日报、制程检验、设备状态 | `/MA产线/1号线/` |
| **按产品型号** | 出货检验、技术规格、质量标准 | `/MA产品/MA80E/` |
| **按工序** | SOP文件 | `/MA工艺/蒸镀工序/` |
| **按设备** | 设备状态、维护记录 | `/ULVAC-EWG165-1号/` |
| **按年份/月份** | 动态数据、实验数据 | `/2026/01/` |
| **按项目状态** | 研发项目文档 | `/进行中/` vs `/已结项/` |
| **按负责人** | 实验数据（可选） | `/张三/` |

### 1.1.2 子路径深度建议

```
推荐最大深度: 5层

/CCC知识库数据源/04_动态数据/生产日报/MA产线/1号线/2026/01/
     ↑              ↑          ↑        ↑      ↑    ↑   ↑
   根目录      一级分类    二级分类  产线   产线号 年份 月份
   (L1)         (L2)        (L3)    (L4)   (L5)  (L6) (L7)

注意: 过深的目录会增加上传难度，建议不超过5-6层
```

### 1.1.3 关键决策：AI自动识别 vs 人工管理子路径

这是一个核心架构选择，两种方式各有优劣：

#### 方案对比

| 维度 | 方案A: 人工管理子路径 | 方案B: AI自动识别分类 |
|-----|---------------------|---------------------|
| **上传门槛** | 高 - 需要知道放哪个目录 | 低 - 随便放，AI自动识别 |
| **准确性** | 高 - 人为保证 | 中 - 依赖AI识别能力 |
| **维护成本** | 高 - 需要培训和检查 | 低 - 自动化 |
| **灵活性** | 低 - 新类型需要建目录 | 高 - 自动适应新类型 |
| **可追溯性** | 高 - 路径即分类 | 中 - 依赖元数据 |
| **技术复杂度** | 低 | 高 - 需要NLP/ML |

#### 推荐方案：混合模式（简化子路径 + AI辅助识别）

```
┌─────────────────────────────────────────────────────────────┐
│                      混合模式设计                            │
├─────────────────────────────────────────────────────────────┤

│  第一层: 人工选择（4个大类，必须）                           │

#### AI自动识别的字段

上传文件后，AI（通过索引脚本）自动从**文件名**和**内容**中提取：

| 字段 | 识别方式 | 示例 |

| 产线编号 | 匹配 `\d号线` 或 `Line\d` | 1号线, Line2 |

| 日期 | 匹配日期格式 | 2026-01-15 |

| 负责人 | 匹配人名清单 | 张三, 李四 |
| 工序 | 关键词识别 | 蒸镀/涂碳/电镀 |

## 2. AI读取机制设计

### 2.1 方案对比

| 方案 | 实现方式 | 优点 | 缺点 | 推荐场景 |
|-----|---------|------|------|---------|
| **A. 本地同步** | 云盘客户端同步到本地 | 简单、离线可用 | 需定期同步、存储占用 | **推荐首选** |
| **B. API直读** | 通过云盘API读取 | 实时、无需存储 | 需开发、依赖网络 | 大规模数据 |
| **C. 导出转换** | 定期导出为AI友好格式 | 格式标准化 | 需人工操作 | 敏感数据 |
| **D. 混合模式** | A+B结合 | 灵活 | 复杂度高 | 长期方案 |

### 2.2 推荐方案：本地同步 + 索引系统

```
┌─────────────────┐      同步      ┌──────────────────┐
│   云盘(远程)     │  ─────────▶   │  本地目录         │
│                 │   云盘客户端   │  /AI同步数据源/   │
└─────────────────┘               └────────┬─────────┘
                                           │
                                           │ 监控变更
                                           ▼
                                  ┌──────────────────┐
                                  │  索引生成器       │
                                  │  (自动脚本)       │
                                  └────────┬─────────┘

### 2.3 索引系统设计

#### 元数据JSON格式
```json
{
  "generated_at": "2026-02-03T10:00:00Z",
  "total_files": 156,
  "categories": {
    "01_内部文档": {
      "file_count": 45,
      "last_updated": "2026-02-02",
      "files": [
        {
          "path": "01_内部文档/运营部/制度流程/CCC-OP-001-生产管理制度.pdf",
          "name": "CCC-OP-001-生产管理制度.pdf",
          "type": "pdf",
          "size_kb": 256,
          "modified": "2026-01-15",
          "keywords": ["生产", "管理", "制度"],
          "summary": "生产部门日常管理制度，包含排班、交接班、考核等内容",
          "sensitivity": "internal"
        }
      ]
    },
    "02_受控工艺文件": { ... },
    "03_实验数据": { ... },
    "04_动态数据": { ... }
  }
}
```

#### 索引生成脚本（自动运行）
```python
# 伪代码 - 索引生成器
def generate_index():
    """扫描同步目录，生成元数据索引"""
    files = scan_directory("/AI同步数据源/")

    for file in files:
        metadata = {
            "path": file.path,
            "name": file.name,
            "type": get_file_type(file),
            "size_kb": file.size / 1024,
            "modified": file.modified_time,
            "keywords": extract_keywords(file),      # 从文件名和内容提取
            "summary": generate_summary(file),       # AI生成摘要
            "sensitivity": classify_sensitivity(file) # 敏感度分类
        }
        index.add(metadata)

    save_json(index, "/_系统文件/元数据/文档清单.json")
```

### 2.4 AI读取流程

```
1. AI读取索引文件 → 了解有哪些文档可用
2. 根据用户问题 → 匹配相关文档
3. 读取具体文档 → 获取详细内容
4. 整合信息 → 回答用户问题
```

| 优先级 | 格式 | AI可读性 | 适用场景 | 注意事项 |
|-------|------|---------|---------|---------|
| 1 | Markdown (.md) | ⭐⭐⭐ | 文字文档、技术文档 | 最佳选择 |
| 2 | CSV/Excel (.csv/.xlsx) | ⭐⭐⭐ | 数据表格、实验数据 | 避免复杂格式 |
| 3 | 纯文本 (.txt) | ⭐⭐⭐ | 日志、简单记录 | 无格式 |
| 4 | PDF (可搜索) | ⭐⭐ | 正式文档、合同 | 需OCR |
| 5 | Word (.docx) | ⭐⭐ | 常规文档 | 格式可能丢失 |
| 6 | PDF (扫描件) | ⭐ | 历史文档 | 需OCR转换 |

### 3.2 数据表格规范

#### Excel/CSV规范
```
- 第一行必须是表头
- 每列有明确的中文列名
- 日期格式: YYYY-MM-DD
- 数值不带单位（单位在表头说明）
- 空值用空白，不用"NA"或"-"
- 每个工作表只放一个数据集
```

| 实验日期 | 实验编号 | 真空度(Pa) | 功率(kW) | 沉积速率(nm/s) | 结果评价 |
|---------|---------|-----------|---------|---------------|---------|
| 2026-01-15 | EXP-MA-001 | 2.5E-4 | 12.5 | 45.2 | 合格 |
| 2026-01-16 | EXP-MA-002 | 3.0E-4 | 13.0 | 48.1 | 优秀 |

## 4. 同步与更新机制

### 4.1 同步频率建议

| 数据类型 | 同步频率 | 说明 |
|---------|---------|------|
| 内部文档 | 每日1次 | 变化较少 |
| 受控工艺文件 | 每日1次 | 版本控制 |
| 实验数据 | 实时/每日 | 根据实验频率 |
| 动态数据 | 每日2次 | 早晚各一次 |
| 参考资料 | 每周1次 | 变化最少 |

### 4.2 变更通知机制

```
1. 索引生成器检测文件变化
2. 生成变更摘要
3. 通知AI助手有新文档
4. AI可主动告知用户新增内容
```

### 4.3 版本管理

```
对于受控文件，保留历史版本:
SOP-MA-001-蒸镀作业程序_v1.0.pdf
SOP-MA-001-蒸镀作业程序_v1.1.pdf
SOP-MA-001-蒸镀作业程序_v2.0.pdf  ← 当前版本
```

## 5. 敏感数据处理

### 5.1 敏感度分级

| 级别 | 标识 | 示例 | 处理方式 |
|-----|------|------|---------|
| 公开 | [公开] | 产品介绍、公开资料 | 无限制 |
| 内部 | [内部] | 制度流程、会议纪要 | 仅内部使用 |
| 机密 | [机密] | 成本数据、客户信息 | 不进入AI知识库 |
| 绝密 | [绝密] | 核心工艺参数 | 不上传云盘 |

### 5.2 敏感文件处理

```
机密和绝密文件:
1. 不放入AI可访问的同步目录
2. 如需AI分析，手动脱敏后提供
3. 记录在排除清单中
```

## 7. Key Decisions

| 决策 | 选择 | 理由 |
|-----|------|------|
| 同步方式 | 本地同步 | 简单可靠，离线可用 |
| 索引格式 | JSON | AI友好，易于解析 |
| 命名规范 | 类型代码+序号+描述 | 便于分类和检索 |
| 敏感数据 | 分级管理，机密不入库 | 安全合规 |
| 更新频率 | 每日同步 | 平衡时效性和资源 |

## 8. Alternative Approaches

### 方案B: 全API模式
- **优点**: 实时性最好，无需本地存储
- **缺点**: 需要开发对接，依赖网络
- **建议**: 作为长期演进方案

### 方案C: RAG向量数据库
- **优点**: 语义检索能力强
- **缺点**: 需要额外基础设施
- **建议**: 文档量>1000份后考虑

## 9. Risk Mitigation

| 风险 | 缓解策略 |
|-----|---------|
| 员工不配合上传 | 与KPI挂钩，简化上传流程 |
| 格式不规范 | 提供模板，定期检查 |
| 敏感数据泄露 | 分级管理，权限控制 |
| 同步延迟 | 提高同步频率，监控告警 |
| AI误读内容 | 索引摘要人工审核 |
