## 关键原则：分阶段信息隔离

```
阶段 1: 问题生成          阶段 2: 盲评            阶段 3: 分层分析
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
```

**类比临床试验**：药物分组（A/B/C）在试验设计阶段确定，但医生和患者在试验期间是**双盲**的。揭盲后才按分组分析结果。

## 具体方案

### 阶段 1: 问题生成（带标签）

我们标注每个问题的：
- 类别（A/B/C）
- 生成方法（①-⑥）
- 预期结果（MCP优/持平/MCP劣）

**这些标签不进入评估流程**，只保存在元数据文件中。

### 阶段 2: 盲评（P21 评估框架）

评委（LLM-as-Judge）收到的信息**只有**：
```
问题: "xxx"
答案 A: "..." (随机编号，不知道哪个是 MCP)
答案 B: "..."

请从准确性、具体性、相关性、可操作性、可信度五个维度打分。
```

评委**不知道**：
- 哪个答案来自 MCP，哪个来自 Vanilla（P21 已有的盲评设计）
- 这个问题属于 A/B/C 哪个类别
- 这个问题的"预期结果"是什么

这样评委无法被预期偏见影响。

### 阶段 3: 揭盲 + 分层分析

评分完成后，合并元数据，做分组统计：

```
总结果: MCP胜率 = X%

按问题类别拆解:
├── A 类 (KB独占): MCP 胜率 = ?%  ← 预期高，验证 KB 价值
├── B 类 (通用知识): MCP 胜率 = ?% ← 预期 ≈50%，验证不干扰
└── C 类 (KB未覆盖): MCP 胜率 = ?% ← 预期低，验证诚实性

按生成方法拆解:
├── 方法①: ...
├── 方法③: ...
└── 方法⑥ (对抗性): MCP 胜率 = ?% ← 压力测试
```

### 阶段 4: 假设验证（用预期结果做 sanity check）

这是**预知类别**的正面用途。如果结果不符合预期，说明：

| 预期 | 实际 | 含义 |
|------|------|------|
| A类MCP应赢 | MCP确实赢 | KB有效（正常） |
| A类MCP应赢 | MCP没赢 | KB检索可能有问题，需调查 |
| B类应持平 | 确实持平 | MCP不干扰（正常） |
| B类应持平 | MCP明显赢 | 说明KB意外地也覆盖了这个话题 |
| C类MCP应输 | MCP确实输 | MCP诚实不幻觉（正常） |
| C类MCP应输 | MCP反而赢 | 要么KB意外覆盖，要么Vanilla太差 |

每个"异常"都值得逐题分析，这正是预知类别的价值。

## 关于对抗性问题（方法⑥）

对抗性问题的目的不是"证明MCP差"，而是**压力测试**。具体来说：

- **过时信息题**：KB 中有旧数据，而 Claude 训练数据可能有更新的 → 测试 MCP 是否盲目引用过时信息
- **KB 矛盾题**：不同文档对同一问题说法不同 → 测试 MCP 是否能识别矛盾
- **KB 边缘覆盖题**：KB 只有间接相关的内容 → 测试 MCP 是否过度推断

这类题数量应少（5-8题），用于发现系统弱点，不用于计算总胜率。
