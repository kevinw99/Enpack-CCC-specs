## 第二阶段：制定对接方案（第3-4周）

> **目标**：根据摸底结果，确定技术方案和优先级。

### 任务2.1：确定数据对接技术路线

收到第一阶段的调查结果后，我们会根据ERP类型选择最合适的对接方式：

**方案A：通过API对接（推荐）**
- 适用于：用友YonBIP、金蝶星空、SAP S/4HANA等新版本
- 优点：安全、标准化、供应商支持
- 工作量：中等（2-4周开发）

**方案B：通过数据库只读视图对接**
- 适用于：老版本ERP（用友U8、金蝶K/3传统版等）
- 优点：灵活、不依赖供应商
- 风险：需要了解数据库表结构，升级时可能受影响
- 工作量：较少（1-2周开发）

**方案C：通过报表/导出文件对接**
- 适用于：无API、不允许数据库直连的情况
- 优点：最低门槛
- 缺点：非实时，需要定期导出
- 工作量：最少（几天开发）

### 任务2.2：确定对接优先级

根据缺口分析，建议按以下顺序对接ERP模块：

| 优先级 | ERP模块 | 服务的问题数 | 原因 |
|--------|---------|------------|------|
| **第1批** | 库存管理 | 5个 | 采购、供应链、生产都需要 |
| **第1批** | 销售/订单管理 | 4个 | 客户分析、交期评估的基础 |
| **第2批** | 成本/财务 | 5个 | 定价决策、利润分析的核心 |
| **第2批** | 采购管理 | 4个 | 采购审批、供应商分析 |
| **第3批** | 生产管理 | 4个 | 良率、产能、排产分析 |
| **后续** | CRM/客户管理 | 6个 | 如果CRM独立于ERP |

### 任务2.3：安全和权限方案

| 事项 | 要求 |
|------|------|
| 访问方式 | **只读**，不允许AI系统写入或修改任何数据 |
| 账户 | 创建专用服务账户，不使用个人账户 |
| 权限范围 | 按模块授权，最小权限原则 |
| 网络 | AI系统运行在公司内网，数据不出外网 |
| 日志 | 记录所有查询操作，可审计 |
| 敏感数据 | 薪资、个人隐私等数据不纳入查询范围 |

## 风险与注意事项

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| ERP没有API，只能导出报表 | 无法实时查询，体验降低 | 改用定期导出+本地缓存方案 |
| IT部门人手不足，无法配合 | 对接延迟 | 先做知识库内容（阶段三），同时协调资源 |
| ERP数据质量差（缺失、不准确） | AI回答不可靠 | 先小范围测试，确认数据质量后再扩展 |
| 管理层担心数据安全 | 项目受阻 | 强调只读访问、内网运行、可审计，先演示再推广 |
| 多个子公司用不同系统 | 对接工作量翻倍 | 先对接高邮工厂（复合集流体），后续再扩展 |
