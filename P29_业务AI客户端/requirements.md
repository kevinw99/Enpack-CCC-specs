# Requirements: P29 业务AI客户端

## 目标

为业务人员提供统一的 Web 聊天界面，整合 KB 知识库 + ERP 数据双 MCP 能力，支持智能模型路由，替代让非技术用户使用 Cursor/Claude Code 的现状。

## 背景

- P20: MCP 知识库服务已就绪（KB 搜索、公司档案、产品、竞品、行业）
- P23: ERP MCP 已就绪（物料、库存、采购、固定资产、期货）
- P28: 模型对比验证了 DeepSeek V4 Flash + 优化 prompt 是最佳性价比方案
- R22: 研发因子筛选工具需要 Web UI，架构可复用
- P22: 6 个研发 AI 工具待集成

## 核心需求

### 1. 聊天界面
- 自然语言问答，业务人员无需知道底层工具
- 显示 AI 回答来源（"根据知识库" / "根据 ERP 数据"）
- 展示工具调用过程（可折叠），增加透明度

### 2. 双 MCP 集成
- KB MCP: 知识库搜索、公司档案、产品、竞品、行业
- ERP MCP: 物料、库存、采购单据、固定资产、期货
- 自动路由：LLM 根据问题决定调用哪些工具

### 3. 智能模型路由
- Router: DeepSeek V4 Flash（快速 JSON 工具规划）
- Answerer: 可配置（Flash 默认，Pro 可选）
- 成本/延迟透明显示

### 4. 扩展性
- 插件式工具注册：新增 MCP 工具只需添加配置
- 未来集成 R22 因子筛选、P22 研发工具等
- 支持多轮对话（上下文保持）

### 5. 权限管理（Phase 2）
- 角色：管理员 / 业务人员 / 研发人员
- 工具可见性按角色控制
- API key 集中管理（用户无需配置）

## Phase 1 MVP (本次实施)

- Streamlit 聊天界面
- 双 MCP 工具（KB + ERP）
- Flash 单模型（P28 验证的最优方案）
- 工具调用可视化
- 无需登录（内部部署）

## Phase 2

- React 前端 + FastAPI 后端
- 用户认证 + 角色权限
- 集成 R22/P22 研发工具
- 对话历史持久化
- 多用户并发
