# Design: KB 适配问题集生成 (P24)

## 方法论

### 临床试验类比

本评估方案借鉴**随机对照试验 (RCT)** 的核心方法论：

| 临床试验概念 | 本项目对应 |
|------------|-----------|
| 实验组 vs 对照组 | MCP 配置 vs Vanilla 配置 |
| 双盲 | 评估者不知道回答来源，也不知道问题类别 |
| 分层分析 | 按 A/B/C 类别揭盲后分别统计 |
| 阳性对照 | A 类问题（预期 MCP 胜） |
| 阴性对照 | C 类问题（预期 MCP 平/负） |
| 安慰剂组 | B 类问题（预期无差异） |

### 三阶段生成 + 四阶段评估

### 去重策略

- 语义相似度 > 0.85 的问题视为重复，保留更自然/更有区分度的一个
- 同一 KB 文档被 3+ 个问题引用时，优先保留不同角度的问题
- **跨类别去重**：B/C 类问题不应与 A 类问题高度重叠

### 区分度验证 (仅 A 类)

对每个 A 类候选问题，评估：
- **Vanilla 能答多少**: 基于 Claude 训练数据中的公开行业知识
- **MCP 能额外提供什么**: KB 中有哪些具体的、专有的信息

只保留 MCP 能提供显著增值的问题（专有数据、具体数字、内部文档引用）。

## 三阶段信息隔离设计

### Phase 1: 回答生成 (knows categories)

- 对每个问题，分别用 MCP 和 Vanilla 配置生成回答
- 生成者知道问题类别（用于调试和质量检查）
- 输出：每题两份回答 + 随机分配的展示顺序 (coin flip)

### Phase 2: 盲评打分 (no category info)

评估者看到的信息：
```
问题: [问题文本]
回答 A: [随机排序的回答 1]
回答 B: [随机排序的回答 2]

请评分 (1-5): 准确性 / 具体性 / 相关性 / 可操作性 / 可信度
哪个回答更好？A / B / 平手
```

评估者**不知道**：
- 哪个回答来自 MCP，哪个来自 Vanilla
- 该问题属于 A/B/C 哪个类别
- 该问题的预期结果是什么

### Phase 3: 揭盲 + 分层分析

评估完成后，揭示类别标签和来源标签，进行分层统计：

| 分析维度 | A 类 (KB独占) | B 类 (通用) | C 类 (对抗) | 全集 |
|---------|--------------|------------|------------|------|
| MCP 胜率 | 预期≥80% | 预期40-60% | 预期≥30% | 加权平均 |
| MCP 平均分 | — | — | — | — |
| Vanilla 平均分 | — | — | — | — |
| 分差显著性 (p-value) | — | — | — | — |

### Phase 4: 假设验证

三个待验证的假设：

| 假设 | 验证方法 | 判定标准 |
|------|---------|---------|
| H1: KB 在覆盖范围内有显著增值 | A 类 MCP 胜率 | ≥80% |
| H2: MCP 不引入副作用 | B 类 MCP 胜率 | 40-60% (不显著偏离 50%) |
| H3: MCP 不编造 KB 未覆盖内容 | C 类表现 | MCP 不显著劣于 Vanilla |

## 对抗性问题设计指南 (C 类)

### 设计原则

C 类问题的目标不是"刁难" MCP，而是检测其在 KB 边界情况下的行为是否合理。

### 三类对抗场景

**1. 过时 KB 信息 (Stale Data)**
- 场景：KB 中包含的某些数据可能已过时（如旧的产能数据、过期的客户信息）
- 示例问题方向：询问最新产能/最新客户动态
- 预期行为：MCP 应能引用 KB 数据但注明数据时效性，而非给出过时信息当作最新事实

**2. KB 内部矛盾 (Contradictory Docs)**
- 场景：不同 KB 文档对同一事实的描述不一致
- 示例问题方向：询问有矛盾描述的主题
- 预期行为：MCP 应综合多个来源，标注不一致之处，而非只引用一方

**3. 边界覆盖 (Edge Coverage)**
- 场景：问题跨越 KB 覆盖与未覆盖区域
- 示例问题方向：部分可从 KB 回答但需要外部信息补充
- 预期行为：MCP 应提供 KB 中可获得的部分，并明确标注无法回答的部分

## 问题变体生成策略

### 从种子问题扩展的方法

| 变体类型 | 例子 |
|---------|------|
| **深度递进** | 种子："我们有哪些竞争对手？" → 变体："宝明科技和金美在技术路线上与我们的差异具体体现在哪些环节？" |
| **角色切换** | 种子："产品定价策略是什么？" → 变体："如果我要向新客户报价复合铜箔，应该参考哪些定价因素？" |
| **对比分析** | 种子："复合铜箔规格" → 变体："4μm和6μm复合铜箔在性能和应用场景上有什么区别？" |
| **场景应用** | 种子："GB38031-2025影响" → 变体："一个客户问我们的产品是否满足新国标的热扩散要求，我该怎么回答？" |

### 从文档反向生成的方法 (方法①)

1. 阅读文档全文
2. 提取关键知识点（数字、结论、流程、对比）
3. 构造"真实业务场景中有人会这么问"的问题
4. 避免"文档里写了什么"式的直接提问

### B 类问题生成策略 (方法③⑤)

B 类问题的关键：答案完全可由公开行业知识推导，KB 不提供额外信息。

| 方向 | 示例 |
|------|------|
| 行业基础知识 | "锂电池正极材料有哪些主要类型？" |
| 公开市场数据 | "中国动力电池市场 2024 年出货量大约是多少？" |
| 通用工艺知识 | "PVD 镀膜的基本原理是什么？" |
| 行业趋势 | "固态电池商业化的主要技术挑战有哪些？" |

### C 类问题生成策略 (方法④⑥)

C 类问题的关键：故意挑战 MCP 的 KB 依赖行为。

参见上方"对抗性问题设计指南"中的三类场景。

## 输出规范

### Python 文件格式

```python

"""KB-adapted question set for fair P21 re-evaluation.

Generated by P24. All questions have KB coverage >= 部分.
Target: measure MCP value-add on KB-answerable questions.
"""

from dataclasses import dataclass, field

@dataclass
class KBQuestion:
    id: str
    question: str
    category: str      # A / B / C
    generation_method: str  # doc_reverse/seed_expand/industry_general/p19_gap/role_sim/adversarial
    expected_outcome: str   # mcp_win / tie / mcp_lose
    domain: str        # company/operations/tech/analysis/industry/research
    kb_sources: list[str] = field(default_factory=list)  # expected KB doc paths
    complexity: str = "中等"
    answer_type: str = "分析"
    kb_coverage: str = "完全"
    seed_source: str = "doc_derived"

QUESTIONS: list[KBQuestion] = [
    # ...
]
```

## 实施步骤

1. **读取所有 KB 文档** — 建立文档内容索引
2. **生成 A 类问题** (V1, 已完成) — 从种子扩展 + 文档反向生成 → 60 题
3. **生成 B 类问题** (V2) — 从行业通识 + 角色模拟 → 15-20 题
4. **生成 C 类问题** (V2) — 从 P19 缺口 + 对抗性设计 → 8-10 题
5. **合并去重** — 跨类别语义去重 + 分布验证
6. **标注元数据** — 每题标注 category / generation_method / expected_outcome
7. **设计盲评协议** — 回答随机化 + 评估表单模板
8. **输出** — 生成 Python + Markdown 文件
