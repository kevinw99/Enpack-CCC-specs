# Requirements: KB 适配问题集生成 (P24)

**创建日期**: 2026-04-13
**状态**: 草稿
**依赖**: P18 (样本问题库), P19 (知识库缺口分析), P21 (MCP问答质量评估)
**输出消费方**: P21 (重新评估KB MCP效果)

---

## 背景与动机

P21 的评估结论存在**公平性问题**：P18 的 52 个样本问题中，KB 完全覆盖仅 2 个 (4%)，54% 完全无覆盖。P21 从中选取了 30 个问题，其中 13 个 (43%) 属于 KB 零覆盖——这些问题本质上在考核 KB 不具备的能力（需要 ERP/CRM 实时数据）。

**结果**：P21 的 MCP 胜率 33%~60% 被 KB 覆盖不足拉低，无法准确反映 MCP 在其能力范围内的真实表现。

**解决方案**：生成一套**专门适配 KB 内容**的评估问题集，确保每个问题都能从 KB 文档中找到实质性答案，从而公平评估 KB MCP 的增值效果。

---

## 目标

1. 生成一套**三类别评估问题集** (80-90 题)，科学衡量 KB MCP 的真实增值效果
2. **A 类 (KB独占优势)**: 55-60 题 — MCP 应明显胜出，问题答案主要来自 KB 专有内容
3. **B 类 (通用知识)**: 15-20 题 — MCP ≈ Vanilla，问题可由公开行业知识回答，KB 无显著增值
4. **C 类 (KB未覆盖/对抗性)**: 8-10 题 — MCP 应平手或略输，问题故意超出 KB 覆盖范围或利用 KB 过时/矛盾信息
5. 采用**盲评方法** (blind evaluation)：评估者仅看到问题 + 两个随机排序的回答，不知道哪个来自 MCP
6. 覆盖 KB 的所有主要知识领域（公司档案、业务运营、技术规范、运营分析、行业背景、研究报告）
7. 保持问题的复杂度和类型分布均衡
8. 生成的问题集可直接用于 P21 重新评估

### 三类别设计原理

| 类别 | 代号 | 题数 | 预期结果 | 验证假设 |
|------|------|------|----------|---------|
| A — KB独占优势 | KB-A-xxx | 55-60 | MCP 胜 ≥80% | KB 在其覆盖范围内提供显著增值 |
| B — 通用知识 | KB-B-xxx | 15-20 | MCP ≈ Vanilla | MCP 不会因为有 KB 而在通用题上变差 |
| C — KB未覆盖/对抗性 | KB-C-xxx | 8-10 | MCP 平手或略输 | 检测 MCP 是否会编造 KB 不含的信息 |

**为什么需要 B 和 C 类**：仅用 A 类问题评估会产生"主场优势"偏差。B 类确认 MCP 不引入副作用；C 类检测 MCP 是否会过度依赖 KB 而产生幻觉或错误引用。三类结合才能给出完整画面。

## 功能需求

### FR-1: 问题生成策略 — 六种方法

| # | 方法 | 适用类别 | 说明 |
|---|------|---------|------|
| ① | **从 KB 文档反向生成** | A | 阅读 KB 文档，提取专有知识点，生成自然业务问题 |
| ② | **从现有种子问题扩展** | A | 对 P18/用户指南种子问题生成变体（不同角度/深度/子话题） |
| ③ | **从行业通识生成** | B | 生成可由公开行业知识回答的问题，不依赖 KB 专有内容 |
| ④ | **从 P19 缺口清单生成** | C | 利用 P19 识别的 KB 缺口，生成 KB 无法覆盖的问题 |
| ⑤ | **角色模拟法** | A/B | 模拟不同角色（销售、工程师、管理层）的典型提问 |
| ⑥ | **对抗性生成** | C | 故意构造 KB 过时信息、矛盾文档、边界覆盖的问题 |

**方法 ① — 从 KB 文档反向生成** (A 类主力)
- 输入：每份 KB 文档的内容
- 方法：阅读文档，提取可以被问到的知识点，生成自然的业务问题
- 确保问题像真实用户会问的，而不是"文档中第三段说了什么"

**方法 ② — 从现有种子问题扩展** (A 类辅助)
- 输入：用户使用指南中的 16 个样本问题 + P18 中 KB 覆盖度≥"部分"的问题
- 方法：对每个种子问题，生成 2-3 个变体（不同角度、不同深度、不同子话题）
- 确保变体不是简单改写，而是探索同一领域的不同侧面

**方法 ③ — 从行业通识生成** (B 类)
- 输入：锂电池/复合箔行业公开知识
- 方法：生成 Claude 训练数据可覆盖的行业通识问题
- 验证标准：Vanilla Claude 也能给出合理回答

**方法 ④ — 从 P19 缺口清单生成** (C 类)
- 输入：P19 识别的 KB 覆盖缺口
- 方法：针对 KB 明确不含的信息领域生成问题
- 验证标准：KB 中无实质性内容可回答

**方法 ⑤ — 角色模拟法** (A/B 类)
- 模拟角色：销售经理、研发工程师、高管、新员工、外部投资者
- 每个角色生成 2-3 个典型场景提问

**方法 ⑥ — 对抗性生成** (C 类)
- 故意使用 KB 中过时的数据设问（如旧产能数据）
- 引用 KB 内部矛盾的信息
- 涉及 KB 边界模糊区域（部分覆盖但不足以完整回答）

### FR-2: 问题质量标准

每个生成的问题必须满足：

1. **可回答性**: KB 中有实质性内容可以回答（不是凑字数的泛泛回答）
2. **自然性**: 问题读起来像真实业务场景中的提问，不是考试题
3. **区分度**: MCP 配置和 Vanilla 配置在该问题上应该有可区分的表现差异
4. **独立性**: 问题之间不高度重叠

### FR-3: 问题元数据标注

每个问题需标注：
- `id`: 唯一编号 (KB-A-001, KB-B-001, KB-C-001 — 按类别分段)
- `question`: 问题文本
- `category`: **问题类别 (A / B / C)**
- `generation_method`: **生成方法 (doc_reverse / seed_expand / industry_general / p19_gap / role_sim / adversarial)**
- `expected_outcome`: **预期评估结果 (mcp_win / tie / mcp_lose)**
- `domain`: 知识域 (company / operations / tech / analysis / industry / research)
- `kb_sources`: 预期可回答该问题的 KB 文档路径列表（B/C 类可为空）
- `complexity`: 简单 / 中等 / 复杂
- `answer_type`: 查询 / 分析 / 建议
- `kb_coverage`: 完全 / 部分 / 无（A 类不应有"无"，C 类应全部为"无"或"部分"）
- `seed_source`: 种子来源 (guide_sample / p18_partial / p18_full / doc_derived / industry / p19_gap / adversarial)

### FR-4: 分布要求

| 维度 | 目标分布 |
|------|---------|
| **类别** | **A: 55-60 题, B: 15-20 题, C: 8-10 题** |
| 知识域 (A 类内) | 每个域至少 5 个问题 |
| 复杂度 | 简单 20-30%, 中等 40-50%, 复杂 20-30% |
| 回答类型 | 查询 20-30%, 分析 35-45%, 建议 25-35% |
| KB 覆盖 (A 类) | 完全≥50%, 部分≤50% |
| 生成方法 | 六种方法均有覆盖 |

### FR-5: 输出格式

- 问题集以 Python 文件输出（与 P21 的 `questions.py` 格式兼容）
- 同时输出 Markdown 版本，便于人工审阅
- 包含覆盖度统计摘要

### FR-6: 与 P21 评估框架兼容

- 问题数据结构与 P21 的 `Question` dataclass 兼容
- 可直接替换 P21 的 `QUESTIONS` 列表进行重新评估
- 保留 P21 的评估维度（准确性、具体性、相关性、可操作性、可信度）

### FR-7: 盲评协议 (Blind Evaluation Protocol)

评估过程中实施信息隔离，确保评估结果不受预期偏差影响：

1. **评估者输入**：仅看到 `问题文本` + `回答 A` + `回答 B`（随机排序，不标注来源）
2. **隐藏信息**：评估者不知道哪个回答来自 MCP、哪个来自 Vanilla；也不知道问题属于 A/B/C 哪个类别
3. **类别标签用途**：仅在评估完成后的 post-hoc 分析阶段揭盲，用于分层统计
4. **随机化**：每题的 MCP/Vanilla 回答展示顺序随机化（50/50 概率），防止位置偏差

---

## 成功标准

1. 生成 80-90 个问题，A/B/C 类别分布符合目标 (55-60 / 15-20 / 8-10)
2. A 类问题中每个知识域至少 5 个
3. 盲评下 A 类问题 MCP 胜率 ≥80%
4. B 类问题 MCP 与 Vanilla 表现无显著差异 (胜率 40-60%)
5. C 类问题 MCP 不显著劣于 Vanilla (胜率 ≥30%)
6. 人工审阅确认问题自然、合理、有区分度

## 非目标

- 不生成需要 ERP/CRM 实时数据的问题（那是 P23 的范围）
- 不执行评估本身（评估是 P21 的工作，本项目只生成问题集 + 定义盲评协议）
- 不修改 KB 内容（如果发现 KB 缺口，记录但不填补）
- 不对 B/C 类问题要求 KB 覆盖（这两类本就不依赖 KB）
