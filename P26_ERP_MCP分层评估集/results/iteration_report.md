## 4. 新发现的回归：L7_refusal -0.333

### 现象

- v1: T0 0.833 / T1 0.500 / T2 0.833
- v2: T0 0.500 / T1 0.167 / T2 0.500

### 根因推测

我给 prompt 加的反伪问题硬约束太强了：
> "涉及采购/销售/库存/生产/财务/固定资产的分析题（即使多步、跨表、需要计算），**必须**至少执行一次 query_bills/query_materials/query_inventory；不允许仅因 schema 未缓存就放弃"

L7 有 6 题全是伪问题（如"员工生日""客户投诉"），其中一些可能字面涉及"员工""客户"等 ERP 关键词，LLM 为了不被判"逃避"，会尝试 query_bills 去找，反而丢失了本该坚持的拒答。

### v3 建议修复（单行改动）

在 SYSTEM_PROMPT 加：

```
伪问题的正面清单（遇到下列类型题必须直接拒答，不要尝试查询）：
- 员工个人信息（生日、婚姻、健康）
- 客户非交易类信息（投诉、满意度、评价）
- 市场情报（竞争对手、市场占有率、行业趋势）
- 生产车间实时感应数据（温度、电流、振动）
- 物流中转详情（通关、报关、集装箱追踪）
- 工艺/配方细节（配方参数、工艺流程图）
```

预期效果：L7 refusal 回到 0.833+，其他指标不变。
