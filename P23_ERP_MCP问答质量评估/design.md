# Design: ERP MCP问答质量评估

## Approach

复用P21验证过的A/B盲评框架，针对ERP数据依赖型问题评估ERP MCP的回答质量。

## 评估流程

```
┌─────────────────────────────┐
│  P18问题库 (52题)           │
│  ↓ 按P19筛选B类缺口        │
│  测试集: 20-30题 ERP问题    │
└──────────┬──────────────────┘
           │
     ┌─────┴─────┐
     ▼           ▼
┌─────────┐  ┌───────────┐
│ Config A │  │ Config B   │
│ Vanilla  │  │ ERP MCP    │
│ LLM     │  │ LLM + ERP  │
│ (no data)│  │ 实时数据    │
└────┬────┘  └─────┬──────┘
     │             │
     ▼             ▼
┌─────────────────────────┐
│  Answer Pairs (A, B)    │
│  Randomized labels      │
└──────────┬──────────────┘
           │
     ┌─────┴─────┐
     ▼           ▼
┌──────────┐  ┌───────────┐
│ DeepSeek │  │ Claude    │
│ Judge    │  │ Judge     │
│ (主评委) │  │ (交叉验证)│

     │              │
     ▼              ▼
┌─────────────────────────┐
│  Scorecard & Report     │
│  + P21对比分析           │
└─────────────────────────┘
```

## 与P21的差异

| 方面 | P21 (KB MCP) | P23 (ERP MCP) |
|------|-------------|--------------|
| 测试对象 | 知识库MCP (静态文档) | ERP MCP (实时数据) |
| 问题类型 | 混合 (含43% KB无法覆盖) | 纯B类缺口 (ERP数据依赖) |
| 数据来源 | markdown文档、研究报告 | ERP系统 (采购、销售、库存等) |
| 可信度评分 | 盲评有偏差 (评委不知有KB) | 改进: 提示评委有系统数据 |
| 预期结果 | MCP优势在具体性和相关性 | MCP优势应在准确性和具体性 |

## 测试配置

### Config A: Vanilla LLM (Baseline)
- Model: DeepSeek (主) / Claude Sonnet (交叉验证)
- System prompt: "你是一个有帮助的商业助手。请根据你的知识回答以下问题。如果你不确定，请说明你不确定。用中文回答。"
- 无ERP数据访问

### Config B: ERP MCP-Augmented
- Model: 同Config A
- System prompt: Enpack内部AI助手 + ERP数据上下文注入
- ERP MCP提供实时数据（通过MCP tools或搜索结果注入）

### Config C (可选): KB + ERP联合
- Model: 同上
- 同时注入KB背景知识 + ERP实时数据
- 测试两个MCP的协同效果

## 可信度维度改进

P21的盲评设计导致评委无法正确评估MCP引用内容的可信度。P23改进方案：

**评委提示增加说明**:
```
注意：其中一个回答可能来自能够访问公司内部系统数据的AI助手。
如果回答中包含具体的数据并标注了数据来源（如"根据ERP系统数据"、
"根据XX月采购记录"等），这类信息应视为有据可查。
请在评分时考虑这一因素。
```

这不会破坏盲评（评委仍不知道哪个是A哪个是B），但让评委能正确理解带来源标注的数据的可信度。

## 工具复用

P21的工具链可直接复用，需做的适配：

| 工具 | 改动 |
|------|------|
| `eval/questions.py` | 新增ERP问题子集 (从P18 B类缺口筛选) |
| `eval/harness.py` | Config B改为调用ERP MCP (而非KB search) |
| `eval/scorer.py` | 评委系统提示增加可信度说明 |
| `eval/report.py` | 无需改动 |

## Key Decisions

- **先评估ERP MCP单独效果**: 不急于做KB+ERP联合评估，先建立ERP MCP的独立基线
- **复用P21框架**: 保持方法论一致，便于横向对比
- **改进可信度评分**: 修正P21发现的盲评偏差，使评分更公平
- **DeepSeek为主评委**: 成本低，可大量运行；Claude做交叉验证

## Risk Mitigation

- **ERP MCP未就绪**: 先完成框架适配和问题集筛选，等ERP MCP可用后立即运行
- **ERP测试数据时效性**: 记录评估时的数据快照时间，确保可复现
- **ERP数据敏感性**: 评估结果中的答案可能包含真实业务数据，注意存储安全
