# Requirements: ERP MCP问答质量评估 (ERP MCP Q&A Quality Evaluation)

## Overview

评估ERP MCP服务对业务问题的回答质量。P19知识库缺口分析表明，52个业务问题中54%完全无覆盖，且这些问题主要依赖ERP/CRM实时数据（B类缺口）。P21已验证KB MCP在其覆盖范围内有效，但大部分业务价值需要ERP数据支撑。本规格专门针对ERP MCP进行公平的质量评估。

## 背景

| 规格 | 结论 | 启示 |
|------|------|------|
| P18 | 收集52个跨7部门的业务问题 | 问题集覆盖了真实业务场景 |
| P19 | KB覆盖率仅4%，54%需ERP数据 | 大部分问题的答案在ERP里，不在KB里 |
| P20 | KB MCP服务就绪 | 静态知识查询能力已具备 |
| P21 | KB MCP胜率33~60%，但43%题目KB无法覆盖 | 评估方法论验证可行，但测试对象不匹配 |

## Objectives

1. 针对ERP数据依赖型问题，评估ERP MCP的回答质量
2. 复用P21验证过的评估框架（盲评、LLM-as-Judge、交叉验证）
3. 产出ERP MCP的量化记分卡，作为MCP对业务实际价值的证据
4. 识别ERP MCP的薄弱环节，指导后续优化

## Scope

### In Scope
- 从P18问题库中选取ERP数据依赖型问题（B类缺口）作为测试集
- Config A: Vanilla LLM（无ERP数据）vs Config B: LLM + ERP MCP
- 使用P21的5维评分（准确性、具体性、相关性、可操作性、可信度）
- LLM-as-Judge自动评分 + 可选人工抽检
- 可选: KB MCP + ERP MCP联合评估（两个MCP同时启用）

### Out of Scope
- KB MCP单独评估（P21已完成）
- ERP MCP的功能开发（由永志负责，独立分支）
- 用户满意度调查（有价值但属于单独研究）

## 测试集设计

从P18的52个问题中，按P19的缺口分析选取B类缺口问题：

| 部门 | B类缺口问题数 | 说明 |
|------|-------------|------|
| 采购部 | 7 | 采购记录、库存、期货数据、供应商档案 |
| 销售部 | 5 | 订单记录、成本数据、客户档案、应收账款 |
| 生产部 | 5 | 生产工单、良率数据、设备记录、排产计划 |
| 供应链 | 5 | 库存、物流费用、在制品、报关系统 |
| 财务部 | 3 | 成本核算、财务报表、预算数据 |
| 管理层 | 1 | ERP全模块汇总 |

预计测试集: 20~30题（从上述B类问题中筛选ERP MCP已支持的场景）

## Evaluation Dimensions

复用P21的5维评分，但调整可信度维度的评分标准：

1. **准确性** (1-5): 数据是否与ERP实际数据一致？
2. **具体性** (1-5): 是否提供了具体的数字、日期、订单号等ERP数据？
3. **相关性** (1-5): 是否真正回答了业务问题？
4. **可操作性** (1-5): 能否直接用于业务决策？
5. **可信度** (1-5): 数据来源是否可追溯到ERP系统？是否标明了数据时效性？

**可信度评分调整**: 评委提示中增加说明——"其中一个回答可能引用了真实的内部系统数据，带有数据来源标注的具体信息应视为有据可查"。这修正了P21中盲评设计导致的可信度评分偏差。

## Success Criteria

- [ ] 测试集确定: 从P18中筛选ERP MCP已支持的B类缺口问题
- [ ] 评估框架适配: 复用P21的harness/scorer/report工具链
- [ ] 完成至少20题的A/B评估
- [ ] 产出量化记分卡和维度分析
- [ ] 识别ERP MCP的主要薄弱环节
- [ ] 与P21结果对比，说明KB MCP vs ERP MCP的互补价值

## Dependencies

- **P18** (样本问题收集) — 提供测试问题集
- **P19** (知识库缺口分析) — 提供B类缺口分类，指导测试集筛选
- **P21** (KB MCP评估) — 提供评估框架和工具链
- **ERP MCP服务就绪** — 永志开发，独立分支，需达到可评估状态
- P21 eval工具链: `eval/harness.py`, `eval/scorer.py`, `eval/report.py`

## Constraints & Assumptions

- ERP MCP需要连接真实ERP系统或测试数据库
- 评估时ERP数据应有明确的时间快照（避免数据变化影响可复现性）
- 评估结果的可信度取决于ERP MCP的数据覆盖范围——只评估已接入的模块

## Questions & Clarifications

- ERP MCP目前支持哪些模块？（采购、销售、生产、库存？）
- 是否有测试环境的ERP数据可用，还是需要连接生产系统？
- 永志的ERP MCP分支预计什么时候可以进行评估？
- 是否需要同时评估KB+ERP联合场景（两个MCP同时启用）？
