> **版本**: 2.0
> **创建日期**: 2026-02-03
> **更新日期**: 2026-02-05
> **状态**: 重建（v1→v2）

---

## 1. 概述

### 1.1 目的

构建一个能够将大型文档分块读取、通过 LLM 提取关键信息、自动匹配知识库现有文件、并将内容注入到相应位置的系统。专门解决：
- 大文档超出 token 限制的问题
- 大量资料难以手动整理到知识库的问题
- 新内容不知道该放到知识库哪里的问题
- **v1 新增**：正则提取器质量差（乱码、碎片、误提取）的问题

### 1.2 核心工作流程

采用 **LLM 驱动的两阶段处理**架构：

```
┌─────────────────────────────────────────────────────────────────────┐
│                    大文档分块处理系统 v2 (LLM 驱动)                    │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  ══════════ Pass 1：LLM 提取 & 整理（生成中间文档）══════════       │
│                                                                     │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐     │
│  │ 1. 读取  │ -> │ 2. 分块  │ -> │ 3. LLM   │ -> │ 4. 按主题│     │
│  │ 多格式   │    │ 100KB/块 │    │ 结构化   │    │ 生成中间 │     │
│  │ 文件     │    │          │    │ 提取     │    │ 文档     │     │
│  └──────────┘    └──────────┘    └──────────┘    └──────────┘     │
│       │               │               │               │            │
│       v               v               v               v            │
│   PDF/DOCX/       大块分块       LLM 理解上下文    中间文档.md      │
│   PPTX/XLSX       (断点续传)     输出结构化JSON    (人工审查点)     │
│                                                                     │
│  ─ ─ ─ ─ ─ ─ ─ ─ [用户审查中间文档] ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─      │
│  │  可选：跳过审查直接进入 Pass 2（系统在合适时机提醒用户）  │      │
│  ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─      │
│                                                                     │
│  ══════════ Pass 2：LLM 匹配 & 注入 ══════════════════════        │
│                                                                     │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐                     │
│  │ 5. LLM   │ -> │ 6. 整块  │ -> │ 7. 报告  │                     │
│  │ 分析KB   │    │ 注入     │    │ 生成     │                     │
│  │ 决定目标 │    │ 到KB文件 │    │          │                     │
│  └──────────┘    └──────────┘    └──────────┘                     │
│       │               │               │                            │
│       v               v               v                            │
│   读取KB结构      注入完整段落     变更汇总                         │
│   LLM匹配目标    替换占位符       来源追溯                         │
│                   追加到章节                                        │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 1.3 v1.0 问题总结与 v2 改进方向

v1.0 使用正则提取器，实际测试暴露以下问题：

| 问题 | 表现 | v2 解决方案 |
|------|------|------------|
| PDF 文本乱码 | 多列排版导致断句混排 | LLM 理解上下文，自动过滤噪声 |
| 目录误提取 | TOC 条目被识别为操作步骤 | LLM 区分 TOC 与实际步骤 |
| 参数名碎片化 | 整句话作为参数名 | LLM 提取简洁的参数名 |
| 去重不足 | 同一内容重复 3-4 次 | LLM 不会在同一块内重复提取 |
| 匹配错误 | 真空系统→铜箔工艺 | LLM 理解语义，精准匹配 |

### 1.4 使用模式

| 模式 | 说明 | 阶段 |
|------|------|------|
| **对话模式** | 在 Claude Code 中交互式处理，用户实时审查 | 先验证 |
| **自动化模式** | 通过 API 批量处理，适合大量文档 | 后建设 |

### 1.5 目标

1. **高质量提取**：LLM 驱动，提取结果可读、准确、结构化
2. **可审查**：中间文档作为人工检查点（可选跳过）
3. **智能匹配**：LLM 理解 KB 结构，精准定位注入目标
4. **自动化**：减少手动整理资料到知识库的工作量
5. **可追溯**：记录内容来源，便于后续核查
6. **可靠**：支持中断恢复，不丢失处理进度

## 2. 功能需求

### FR-01: 多格式文件读取与大块分块

- **描述**：将大文件按大块读取，充分利用 LLM 上下文窗口
- **验收标准**：
  - [ ] 支持格式：.txt, .md, .docx, .xlsx, .pptx, .pdf
  - [ ] 默认块大小：100KB（充分利用 LLM 上下文窗口）
  - [ ] 块之间重叠 2000 字符以保持上下文连续
  - [ ] 在自然边界处切分（段落、章节、表格边界）
  - [ ] 支持可配置的块大小（1KB - 200KB）

### FR-02: LLM 结构化提取

- **描述**：使用 LLM（Claude Opus）从每个块中提取结构化信息
- **验收标准**：
  - [ ] **工艺参数**：提取简洁的名-值-单位三元组
  - [ ] **操作步骤**：提取完整有序的步骤流程，保持逻辑连贯
  - [ ] **设备信息**：提取设备名称、型号、规格参数
  - [ ] **数据表格**：保留表格结构和表头
  - [ ] **噪声过滤**：自动跳过目录条目、页眉页脚、页码、乱码
  - [ ] **上下文理解**：根据上下文推断不完整内容
  - [ ] LLM 输出结构化 JSON，系统解析为内部数据结构
  - [ ] 每条提取标记来源文件和块索引

### FR-03: 中间文档生成（审查检查点）

- **描述**：将 LLM 提取结果按主题组织为可读的中间 Markdown 文档
- **验收标准**：
  - [ ] 按主题自动分组（多个源文件可归入同一主题）
  - [ ] 生成结构化 Markdown：参数表、步骤列表、设备信息
  - [ ] 每条内容标注来源文件
  - [ ] 输出到 `outputs/intermediate/{主题名}.md`
  - [ ] **审查提醒**：生成后提示用户审查，同时提供"跳过审查直接注入"选项
  - [ ] 对话模式下，中间文档内容直接展示给用户

### FR-04: LLM 智能匹配

- **描述**：使用 LLM 分析中间文档内容与 KB 结构，决定注入目标
- **验收标准**：
  - [ ] 读取 KB 文件列表、章节结构、已有内容摘要
  - [ ] LLM 决定每段内容应注入到哪个文件的哪个章节
  - [ ] 支持匹配到已有章节（追加）或占位符（替换）
  - [ ] 当内容与现有 KB 无匹配时，建议新建文件
  - [ ] 输出匹配方案供用户确认（dry-run 模式）

### FR-05: 整块注入

- **描述**：将匹配好的内容整块注入到 KB 文件
- **验收标准**：
  - [ ] **替换占位符**：目标章节有 `[待补充]` 时替换
  - [ ] **追加到章节**：目标章节无占位符时追加到末尾
  - [ ] **新建章节**：目标章节不存在时创建
  - [ ] 注入内容标记来源（`<!-- 来源: 文件名 -->`）
  - [ ] 支持 dry-run 预览模式
  - [ ] 注入前自动备份目标文件

### FR-06: 进度追踪与断点续传

- **描述**：追踪处理状态，支持中断后恢复
- **验收标准**：
  - [ ] 每个块的 LLM 提取结果持久化保存
  - [ ] 启动时自动检测并恢复已有进度
  - [ ] 提供强制重新开始选项

### FR-07: 处理报告

- **描述**：处理完成后生成变更报告
- **验收标准**：
  - [ ] 处理统计（块数、提取条数、匹配数）
  - [ ] KB 变更清单（更新了哪些文件、哪些章节）
  - [ ] 来源追溯（每条注入内容的原始来源）

### FR-08: 边界情况

- **验收标准**：
  - [ ] 空文件：检测并跳过
  - [ ] 不支持的格式：显示支持格式列表
  - [ ] 超大文件（>100MB）：警告并请求确认
  - [ ] 损坏文件：尝试部分读取，报告损坏位置
  - [ ] 重复内容：LLM 提取层自然去重 + 跨块去重

### FR-09: 日志系统

- **验收标准**：
  - [ ] 记录每个块的 LLM 调用和提取结果
  - [ ] 记录匹配决策
  - [ ] 记录所有 KB 变更

## 3. 知识库集成规范

### 3.1 知识库结构

系统需要理解双知识库的目录结构：

```
知识库/ (public)          +  private/知识库/ (private)
├── 03_技术规范/               ├── 03_技术规范/
│   ├── 01_制造工艺/           │   ├── 01_制造工艺/
│   ├── 02_材料体系/           │   ├── 02_材料体系/
│   ├── 03_产品与质量/         │   ├── 03_产品与质量/
│   └── 04_设备与技术/         │   └── 04_设备与技术/
```

路径配置通过 `config/workspace.yaml` 管理。

### 3.2 匹配策略

v2 不再使用规则评分，改为 **LLM 决策**：

1. 系统读取 KB 文件列表和每个文件的章节结构
2. 将 KB 结构 + 中间文档内容一起传给 LLM
3. LLM 输出匹配方案（JSON 格式）：
   ```json
   {
     "matches": [
       {
         "content_summary": "蒸镀温度等5个工艺参数",
         "target_file": "01_制造工艺/MA复合铝箔制造工艺.md",
         "target_section": "工艺参数",
         "action": "append",
         "reason": "MA蒸镀相关的工艺参数应归入MA复合铝箔制造工艺"
       }
     ]
   }
   ```

### 3.3 注入格式

```markdown
## 原有章节标题

原有内容...

### 新增内容

新注入的内容（完整段落/表格/步骤）

<!-- 来源: 源文件名.pdf -->
<!-- 注入时间: 2026-02-05 -->
```

## 4. 用户界面

### 4.1 对话模式（Phase 1 优先实现）

在 Claude Code 对话中直接操作：

```
用户: 处理 上传文档/MA设备技术资料/蒸发舟使用手册.pdf，注入到知识库

Claude Code:
  1. 读取文件，分为 3 个块
  2. 逐块提取结构化信息
  3. 生成中间文档:

     --- 中间文档预览 ---
     ## 工艺参数
     | 参数 | 值 | 单位 |
     | 蒸发速度 | 0.4~0.5 | g/min·cm² |
     ...

     ## 操作步骤
     1. 电压由 0~2.5V 缓慢升压...
     ...

  4. 提示: 中间文档已生成。是否审查后再注入？
     [直接注入] [我先看看] [跳过此阶段以提高效率]

  5. 匹配 KB 目标，展示匹配方案
  6. 用户确认后注入
```

### 4.2 自动化模式（Phase 2 后续建设）

```bash
# 处理单个文件
python -m chunked_processor.main process "源文件.pdf" --dry-run

# 处理多个文件
python -m chunked_processor.main process "文件夹/*.pdf" --dry-run

# 跳过中间文档审查
python -m chunked_processor.main process "源文件.pdf" --skip-review

# 选项
--dry-run           预览模式，不实际修改文件
--skip-review       跳过中间文档审查步骤
--chunk-size <KB>   块大小（默认：100）
--model <model>     LLM 模型（默认：claude-opus-4-5-20251101）
--output-report     输出处理报告
```
