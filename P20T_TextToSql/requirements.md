# Requirements: P20T TextToSql

## Overview

基于金蝶云星空 MCP Server，构建一套能够准确回答企业内部业务问题的 AI 知识问答系统。
核心挑战是：AI 需要知道"该查哪张表、字段是什么意思、状态值代表什么业务含义"，
才能通过 MCP 工具查到正确数据，给出可信的回答。

当前 V0.1 方案（人工维护 `问题库回答指南.md`）已验证可行，但存在三个瓶颈：
1. 指南越写越大，AI 每次要读整个文件，上下文消耗随内容增长而恶化
2. 字段枚举值（A/B/C 状态）只有业务人员知道，AI 自己发现不了
3. AI 踩坑后的修正没有自动沉淀回去，下次仍会重犯

本项目目标是建立一个**语义层（LLM Wiki）+ 执行层（MCP Server）**的两层架构，
解决上述三个问题，将问答准确率从当前不稳定状态提升到可生产使用的水平。

## 背景与现状

### 已完成
- MCP Server 工具链跑通（金蝶 ERP 查询 + 期货数据）
- 样本问题库 52 题，覆盖 7 个部门
- 已完成答案文档 10 题（约 19%）：q001, q002, q004, q005, q006, q009, q011, q012, q013, q019
- `问题库回答指南.md` 人工维护，记录了部分业务数据流

### 已识别的问题分类

| 状态 | 数量 | 例子 |
|------|------|------|
| 可回答（ERP 有数据） | ~24 题 | Q001, Q002, Q006, Q009... |
| 无相关数据（ERP 缺失） | ~10 题 | Q018 生产进度、Q020 设备故障、Q021 产能利用率 |
| 伪问题（数据不存在） | 3 题 | Q007 采购合同、Q010 采购预算、Q016 销售目标 |

### 核心痛点（来自 2026-04-09 讨论记录）
- AI 幻觉率高：Q013 回答反复修正 3 次才正确（字段选错、状态值混淆）
- 上下文消耗大：`kingdee_describe_form` 每次返回 65KB 全量字段
- 缺乏业务语义层：AI 知道金蝶 ERP 系统，但不知道公司内部个性化的数据流

## Objectives

1. **建立 LLM Wiki 语义层** — 将 `问题库回答指南.md` 的人工知识结构化为可检索的 Wiki 页面
2. **实现问题路由** — 自动判断问题类型，分发到 Wiki 检索或 MCP 查询
3. **建立知识沉淀回路** — AI 纠错后的正确答案自动追加到相关 Wiki 页面
4. **处理伪问题/数据缺口** — 将无法回答的问题显式写入 Wiki，避免 AI 编造
5. **提升问答准确率** — 消除 Q013 式的字段选错、状态值混淆问题

## Scope

### 包含范围
- LLM Wiki 骨架搭建（Obsidian + Git，按业务主题分页）
- 将现有 `问题库回答指南.md` 拆分为 10-15 个 Wiki 页面
- 问题路由规则配置（CLAUDE.md 更新）
- 伪问题/数据缺口的显式标注
- 知识沉淀机制（成功案例追加到 Wiki）
- 样本问题库剩余 ~42 题的答案补全

### 排除范围
- Text2SQL 完整实现（需要完整 DDL + 大量标注，是长期工程）
- Vanna 框架集成（可作为后续演进方向）
- 向量数据库 / RAG 基础设施（文档量不足以支撑）
- ERP 系统本身的改造

## Success Criteria

- [ ] LLM Wiki 骨架建立，至少 10 个业务主题页面
- [ ] `问题库回答指南.md` 内容完整迁移到 Wiki
- [ ] Q013 类问题（状态值混淆）不再复现
- [ ] 样本问题库可回答的 ~24 题全部有答案文档
- [ ] 伪问题/数据缺口全部在 Wiki 中显式标注
- [ ] CLAUDE.md 更新，包含 Wiki 检索路由规则

## Constraints & Assumptions

### 约束条件
- 不能引入新的基础设施（无向量数据库、无额外服务器）
- Wiki 必须对业务人员可读可编辑（Markdown 格式）
- 字段枚举值必须由业务人员确认，AI 不能自行推断

### 假设条件
- 业务人员（吕经理等）愿意配合确认字段含义和状态值
- MCP Server 工具链保持稳定（不做大改）
- 使用 Obsidian 作为 Wiki 编辑器（已在 mcp-kingdee-server 目录下配置）

## Dependencies

- 现有 MCP Server（`源代码/mcp-kingdee-server/src/`）
- 现有 `问题库回答指南.md`（人工知识来源）
- 现有 `样本问题库.md`（52 题）
- 业务人员配合确认枚举值和数据流

## Questions & Clarifications

1. Wiki 存放位置：放在 `源代码/mcp-kingdee-server/wiki/` 还是独立目录？
2. 路由规则的粒度：按问题类型（查数据/查定义）还是按部门？
3. 知识沉淀的触发时机：每次回答后自动追加，还是人工审核后追加？
4. 伪问题的处理：直接在 Wiki 标注"无此数据"，还是需要给出替代方案？
